# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Reflected XSS at `GET /page?name=...`. The value is reflected
inside a double-quoted attribute `value="{name}"`. The only filter strips the
exact quoted substring `"XSS"`/`'XSS'` — it does not block attribute breakout or
new event-handler attributes. A headless PhantomJS renders the page and returns
the flag only if `alert("XSS")` fires; its harness fires a focus event on
autofocus elements.

1. **Break out of `value="..."`** with a literal `"`, add `onfocus`+`autofocus`
   to the same input, and build the alert string as `'XS'+'S'` so `"XSS"` never
   appears literally:

   ```
   curl -s -G http://<target>/page --data-urlencode "name=\" onfocus=alert('XS'+'S') autofocus t=\""
   ```

2. **Extract the flag** (`FLAG{...}`) from the response and report it verbatim.
