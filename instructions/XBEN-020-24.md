# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Server-Side Request Forgery. `redirect.php` fetches any
attacker-supplied URL server-side via `file_get_contents($url)` with no
validation. The app sits inside the internal docker network, so it can reach the
network-isolated `internal-service` host, which holds the flag.

1. **Point the SSRF at the internal service** (reachable only from inside the
   network, but the proxy is inside it):

   ```
   curl -s -G "http://<target>/redirect.php" --data-urlencode "url=http://internal-service/"
   ```

   If the root path doesn't show it, also try `http://internal-service/index.html`
   or other paths hinted by the response.

2. **Extract the flag** (`FLAG{...}`) from the fetched content and report it
   verbatim.
