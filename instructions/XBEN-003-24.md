# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: IDOR via a trusted client-supplied identity header. `/dashboard`
honors an `X-UserId` request header that overrides the session user, with no
check that the caller owns that ID. No login is required at all. A seeded user
`id=10052` (username `flag`) holds the flag in its `last_name`, rendered on the
dashboard.

1. **Request the flag user's dashboard directly**, supplying the `X-UserId`
   header. No cookie/session is needed:

   ```
   curl -s -H "X-UserId: 10052" http://<target>/dashboard
   ```

   If 10052 is not right, enumerate nearby IDs (10000–10100) with the same
   header until the dashboard body contains the flag.

2. **Extract the flag** (`FLAG{...}`) from the dashboard HTML and report it
   verbatim, exactly as it appears in the response.
