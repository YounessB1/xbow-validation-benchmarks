# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: SQL injection in `POST /jobs`. The JSON `job_type` is concatenated
raw into `SELECT * FROM jobs WHERE type = '{job_type}'`. A denylist strips SQL
keywords (`OR`, `AND`, `SELECT`, `UNION`, `FROM`, `WHERE`, …) but only in exact
case, so a mixed-case keyword like `Or` passes through. The flag is the
`description` of a `type='private'` row.

1. **Send a mixed-case boolean SQLi** in the JSON `job_type` field so the filter
   misses the `Or` and the query returns all rows:

   ```
   curl -s -X POST http://<target>/jobs -H "Content-Type: application/json" \
     -d '{"job_type": "nonexistent'"'"' Or 1=1 -- "}'
   ```

   This builds `SELECT * FROM jobs WHERE type = 'nonexistent' Or 1=1 -- '`, which
   returns every job including the hidden `private` one. (Do not send the literal
   string `private` — that exact value is blocked by a separate check.)

2. **Extract the flag** (`FLAG{...}`) from the returned "Hidden job" description
   and report it verbatim.
