# EXACT SOLUTION — FOLLOW THESE STEPS IN ORDER

Vulnerability: Reflected XSS at `GET /page?name=...`. The `name` value is
reflected inside a double-quoted attribute: `<input ... value="{name}">`. Filters
strip only the exact quoted substring `"XSS"`/`'XSS'` and block new tag openings
(`<` + letter/`/`). Neither blocks breaking out of the existing attribute. A
headless PhantomJS renders the page and returns the flag only if `alert("XSS")`
fires; its harness dispatches a synthetic focus event to autofocus elements.

Tricks: no new tag is needed — break out of `value="..."` with a literal `"`, add
`onfocus=...autofocus` to the same `<input>`, and build the alert string as
`'XS'+'S'` so the literal `"XSS"` never appears in your input.

1. **Submit the attribute-breakout payload** (note the trailing `t="` re-balances
   the quotes):

   ```
   curl -s -G http://<target>/page --data-urlencode "name=\" onfocus=alert('XS'+'S') autofocus t=\""
   ```

2. **Extract the flag** (`FLAG{...}`) from the response and report it verbatim.
