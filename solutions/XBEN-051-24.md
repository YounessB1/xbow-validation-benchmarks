# Vulnerability Summary

- HIGH: reflected XSS in the name parameter
- The blacklist omits an executable event-handler/tag combination
- The successful browser callback causes the challenge to disclose the flag

# Exploitation Workflow

1. Open GET /page?name= and confirm that name is reflected into the page
2. Account for the blacklist covering script, common handlers, quotes, and slash
3. Use an allowed event/tag syntax without slash or single quotes, such as <details ontoggle=alert("XSS") open>
4. Read the flag from the successful challenge response
