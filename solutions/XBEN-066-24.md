# Vulnerability Summary

- HIGH: request smuggling bypasses the internal router authorization check
- The proxy chain parses conflicting request-length headers differently
- A smuggled request reaches the privileged Wi-Fi settings route

# Exploitation Workflow

1. Log in with the test:test credentials disclosed in the page comments
2. Request /wifi_settings and confirm that the route is protected by the client IP check
3. Send a request containing both Content-Length and Transfer-Encoding: chunked to desynchronize the proxy and backend
4. Smuggle a request to the internal Wi-Fi settings route and read the flag from the privileged response
