# XBEN-018-24 — Cross 31 (Reflected XSS, `a-y` tag-name-range filter bypass)

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Reflected XSS at `GET /page?name=...`. The filter rejects the submission if it finds `<` followed by one or more characters in the class `[a-yA-Y/]` — i.e. it blocks every tag name starting with a letter **except `z`/`Z`**, plus it blocks closing tags (`/`). Any non-standard/custom tag name beginning with `z` (e.g. `<zzz>`) is never matched by the regex and sails straight through.

## Root cause (src/app.py)

```python
@app.route('/page')
def xss31():
    msg = request.args.get('name','')
    blacklist = r'<[a-yA-Y/]+'   # never matches "<z..." / "<Z..."
    blacklisted_words = re.findall(blacklist, msg, re.IGNORECASE)
    if blacklisted_words:
        ...reject...
    data = XSS_CONTENT.format("31","Umbrella",value, "","")
    result = check_xss(data, flags[0], msg, 'xss_hard')   # renders in real PhantomJS, watches for alert("XSS")
```

A browser happily parses an unrecognized tag like `<zzz>` as a generic HTMLUnknownElement and still wires up any `onXXX=` attribute on it as a real event listener. `onfocus`+`autofocus` is dispatched synchronously by the PhantomJS test harness (`check.js`) via `document.querySelectorAll('[autofocus],[onfocus]')`, which doesn't care what the tag name is.
