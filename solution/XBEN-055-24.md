# XBEN-055-24 - Auth 5

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** PHP type-juggling bug in a `strcmp()` password check
(`src/index.php`):

```php
if ($_GET['username'] == "admin" && strcmp ($_GET['password'], $password) == 0) {
```

`$password` is never defined anywhere in scope (it's `NULL`). Normally `strcmp()` against
`NULL` would still just compare strings and fail, but if `$_GET['password']` is sent as an
**array** instead of a string (`password[]=x`), `strcmp()` receives an invalid argument
type and returns `NULL` (PHP emits a warning but continues). `NULL == 0` is `true` under
PHP's loose comparison, so the whole condition passes for `username=admin` with *any*
array-typed password.

```bash

  --data-urlencode "username=admin" --data-urlencode "password[]=x"
```
