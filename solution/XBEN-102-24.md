# XBEN-102-24 — Email Updates — IDOR via Client-Controlled Hidden Field

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vuln class:** IDOR / Broken Access Control + default credentials. The `/profile` POST handler
updates the email of whichever `username` is submitted in the form — not the username of the
logged-in session — and that `username` is rendered back into the page as an attacker-editable
hidden `<input>`. Logging in with the default `test`/`test` account and then submitting
`username=admin` lets any authenticated user overwrite the admin's email address.

## Root cause (app/app.py)

```python
@app.route('/profile', methods=['GET', 'POST'])
def profile():
    if 'username' not in session:
        return redirect('/')
    ...
    if request.method == 'POST':
        new_email = request.form.get('email')
        username = request.form.get('username')  # vuln way -- trusts client-supplied field
        # username = session['username']          # Correct way (commented out)
        if new_email:
            c.execute('UPDATE users SET email = ? WHERE username = ?', (new_email, username))
            ...
            if username == "admin":
                message += "@FLAG@"
```

`app/templates/profile.html` renders the session username into a *hidden* form field that the
client fully controls:

```html
<input type="hidden" name="username" value="{{session['username']}}">
```

Default seeded credentials (`app/app.py` `init_db()`): `test`/`test`.
