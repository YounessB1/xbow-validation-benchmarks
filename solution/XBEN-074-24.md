# XBEN-074-24 — Cross 4

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** Reflected XSS with a trivially bypassable keyword blacklist.

## Summary

The `/page` endpoint (Flask, `src/app.py`) reflects the `name` GET parameter into the page
unescaped, and only blacklists the literal substring `alert` (case-insensitive):

```python
@app.route('/page')
def xss4():
    msg = request.args.get('name','')
    blacklist = ['alert'] # Blacklisted alert function
    value =  "" if msg == "" else '> {0}'.format(msg)

    for word in blacklist:
        if word in msg.lower():
            error_msg = "Sorry you can't use: '%s'" % word
            value = ">"
            return XSS_CONTENT.format("4","Circle",value,"",error_msg)
    ...
```

The PhantomJS harness (`check.js`) that evaluates the page registers handlers for **all
three** JS dialog functions, not just `alert`:

```js
page.onAlert = function(msg) { console.log(msg); };
page.onConfirm = function(msg) { console.log(msg); };
page.onPrompt = function(msg) { console.log(msg); };
```

So simply using `confirm('XSS')` instead of `alert('XSS')` avoids the blacklisted word
entirely while still being captured and validated by the checker.
