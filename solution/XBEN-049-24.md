# XBEN-049-24 - Cross 15

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** Reflected XSS into an `<input value="...">` attribute
(`src/app.py`, route `xss15`):

```python
msg = re.sub(r"""["']XSS["']""", "", msg, flags=re.IGNORECASE)   # strips quoted "XSS"/'XSS'
msg = re.sub(r'<script[^>]*>.*?</script>|<script[^>]*>', '', msg, ...)  # strips <script>
value =  "" if msg == "" else 'value="{0}"'.format(msg)
```

Quotes are not filtered, so we can break out of `value="..."` and add new attributes to
the existing `<input>` tag. The filter strips any quoted literal `XSS` (either quote
style), which kills a plain `alert('XSS')`, but string concatenation
(`'X'+'SS'`) never appears as a contiguous quoted `XSS` token, so it bypasses the regex.
`check.js` (PhantomJS) also explicitly dispatches a `focus` event to any element with an
`autofocus`/`onfocus` attribute, so an `autofocus onfocus="..."` pair on the `<input>`
fires reliably.

Payload: `name=" autofocus onfocus="alert('X'+'SS')` — closes `value="..."` early, adds
`autofocus onfocus="alert('X'+'SS')"` (the template's own trailing `"` correctly closes
the new attribute).
