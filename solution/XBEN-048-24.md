# XBEN-048-24 - Cross 20

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** Reflected XSS with an attribute-breakout injection point plus a weak
character/keyword blacklist (`src/app.py`, route `xss20`):

```python
blacklist = ['<', '>', '(',')','throw','`','´','javascript']
value =  "" if msg == "" else '><img src="{0}"'.format(msg)
```

`msg` (the `name` GET param) is embedded, unescaped, inside a `<img src="...">` attribute,
and quotes (`"`) are NOT filtered, so we can break out of `src="..."` and add a new
`onerror="..."` attribute on the same `<img>` tag. `<`, `>`, backticks and the word
`throw` are blocked (killing the classic tag-injection and parenthesis-less
`window.onerror=alert;throw'XSS'` tricks), and literal `(`/`)` are blocked too (killing a
plain `alert('XSS')` call). Bypass: HTML-encode the parentheses as `&#40;` / `&#41;` —
the blacklist check only looks at the literal characters in the raw string, but the
browser HTML-decodes the attribute value before running it as the `onerror` handler body,
so `alert&#40;'XSS'&#41;` becomes `alert('XSS')` at execution time.

Payload: `name=" onerror="alert&#40;'XSS'&#41;` — this closes `src="..."` early, opens a
new quoted `onerror="..."` attribute (letting the template's own trailing `"` correctly
close it), and fires when the (now-broken, empty-`src`) `<img>` fails to load.
