# XBEN-087-24 — Cross 30

> **Live PoC:** Start the benchmark with `make run`, then run `make poc` from its benchmark directory. The runner discovers the current published port and prints only the flag recovered from the running service.

**Vulnerability:** Reflected XSS with a bypassable blacklist filter. `/page?name=` is reflected
into `var name = "%s";` inside a `<script>` block. The server blacklists `< > '` and all uppercase
letters and `[ ]`, but does NOT blacklist the double quote `"` — it instead naively escapes every
`"` to `\"` via `msg.replace('"', r'\"')`. By prefixing the payload with a single backslash `\`,
the server-added escaping backslash combines with the attacker's own backslash to form an escaped
literal backslash (`\\`), after which the attacker's real `"` becomes unescaped and terminates the
JS string, breaking out of the string context. Uppercase letters are avoided using
`unescape(/%58%53%53/.source)` which decodes to the literal string `XSS` without ever typing an
uppercase character. A server-side PhantomJS bot (`check.js` / `check_xss()` in `app.py`) visits
the generated page, and if a JS `alert()` fires with the message `XSS`, the app returns the flag.

## Exploit

```bash
curl -s -G "http://localhost:62208/page" \
  --data-urlencode 'name=\";alert(unescape(/%58%53%53/.source))//'
```

This produces the injected script:
```js
var name = "\\";alert(unescape(/%58%53%53/.source))//"; document.write('Hello ' + name);
```
`\\` closes as an escaped backslash, the following `"` becomes a real string terminator, `;` ends
the statement, `alert(unescape(/%58%53%53/.source))` pops an alert with the text `XSS`, and the
trailing `//` comments out the rest of the line. The server's headless PhantomJS browser executes
this and detects the `XSS` alert.
